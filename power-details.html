Power: technical details

How eXcontrol turns an LED installation on, puts it to standby and turns it off, for one screen or a whole venue. This covers what each button does, who decides, the order things happen in, and the rules that protect the hardware. New to this? Start with the simple overview.

1 · The short version

Four ideas explain everything else

One bar for the room

Turn on · Standby · Turn off

The power bar at the top of the dashboard controls the whole room. It shows the room's state in one word and the next scheduled change. Turning the room off or to standby needs a second tap to confirm.

Groups

Parts of the room have their own target

A group (e.g. LED wall, Screens) is a named set of devices with a target: On, Standby or Off. If a device is in two groups, it follows the higher target, so switching one group off never cuts something another group still needs.

EPS power

If it's on an EPS, the EPS decides

A device fed by an Expromo EPS power unit is turned off by switching off its relay. eXcontrol starts units one at a time, never cuts power that something else still needs, and checks every command it sends.

Nothing is fought

It acts when a target changes

eXcontrol carries out a change once, then watches. If someone turns a screen back on with a remote or another controller, eXcontrol doesn't switch it off again. It shows a pop-up so you know.

2 · The pieces

How devices are wired to power

An Expromo EPS has six relays ("outputs"). During setup, each device is given Powered by: which EPS feeds it, and optionally which one output. That setting is all eXcontrol knows about the wiring, so it has to be right.

Output ownership

A device with an output set owns that output. Devices without one share all the rest. A device with no Powered by is on its own socket.

Protected output

For the network switch or the control PC. The room, a group or a schedule never switches it off, because eXcontrol would lose its own connection. Its own button in Power › Details still works.

Spare outputs

Outputs that no configured device depends on (lights, passive loads, a spare unit) follow only the room. A group never touches them.

3 · Who decides

How each device gets its target

Buttons and schedules never switch devices directly. They set a target on the room or on a group. eXcontrol then works out each device's target and carries it out.

  1. The room passes its target down. Setting the room (the power bar, or a schedule entry for the whole room) sets every group to the same target and clears any per-device overrides.
  2. Highest wins. A device in several groups follows the highest target among them: On beats Standby, which beats Off.
  3. No group, then the room. A device that isn't in any group follows the room's target.
  4. The device's own card overrides until one of its groups changes next. Turning something back on from its card doesn't raise a "turned on after its scheduled off" pop-up.
After a restart, group targets start as "not set", and eXcontrol switches nothing at start-up. Things stay as they are until the next change: a button, or the next schedule entry.

5 · Order of work

What happens, step by step, when a target changes

Each change runs as one job, in a fixed order. If a newer change arrives while a job is running, the newer one wins. Progress is shown live in the power bar.

  1. Soft off. Devices that aren't losing their power go to Standby or Black over the network. That covers everything set to Standby, screens on their own socket, and devices kept powered for someone else.
  2. Switch-offs. EPS units in reverse order. The relays switch off at current zero, so switching off needs no stagger, only the right order.
  3. Switch-ons. One EPS unit at a time, with a 1 s gap between units, so there is only one inrush at a time. A unit that is fully off uses its own built-in sequence. Otherwise only the missing outputs are switched on, 300 ms apart.
  4. Wait, then wake. eXcontrol waits for each device to come online (up to 4 min each), then wakes the screens 2 s apart and releases Black on the NovaStar processors it blacked out.

6 · EPS safety rules

The rules eXcontrol follows with every EPS command

Each rule comes from testing a real unit. eXcontrol applies them to every command, wherever it comes from: the power bar, a group, a schedule, Companion or the API.

Never restart running equipment

On a partly-on unit, POWER_ON first switches everything off, then re-sequences, so running equipment loses power for about 1 s. eXcontrol only sends POWER_ON to a fully-off unit. Otherwise it switches on just the missing outputs.

Don't interrupt a sequence

A single-output command sent during the unit's own sequence aborts it, and the remaining outputs never come on. eXcontrol waits for the sequence to finish.

One connection at a time

Two connections at once can make the unit drop both commands, then ignore everything for ~10 s. eXcontrol keeps one queue per unit, and status checks wait while a command runs.

Verify, then retry

Every command is confirmed by reading the status back, and retried up to 3 times if it didn't take. Repeating a command is harmless. This also recovers from collisions with other controllers.

Minimum off-time: 30 s

An output stays off at least 30 s before it's switched on again. This protects inrush limiters, and processors and Android screens aren't hard-cycled. eXcontrol shows a notice while it waits. It can be set per unit.

Patience before a fault

An EPS is shown as Not responding only after 3 missed status checks in a row, not after one lost reply.

7 · After power returns

Starting up, and the power-on default scene

Boot allowance

Up to 4 minutes to start

When an EPS comes on, its equipment gets up to 4 minutes to start before a missing device counts as a problem. Meanwhile the room shows Starting… and names what it's waiting for. A device whose own output is switched off is expected to be silent. It shows No power, not a fault.

Default scene

Brightness and inputs back to normal

A scene can be marked as the power-on default for one EPS, or for all. When that EPS goes from off to on, eXcontrol waits 4 s, applies the scene, and applies it again 9 s later (controllers sometimes overwrite settings while they finish booting). It only covers devices on that EPS.

It only runs if eXcontrol saw the unit off first. Restarting eXcontrol next to a wall that's already on doesn't reset anything.

After a building power cut, what each EPS does depends on its own Restore after reboot setting (in its web page). eXcontrol can't start units in sequence while it's still booting itself. On sites with several EPS units on one supply, keep restore off and let a schedule or the power bar bring the room up.

8 · Schedule

Timed changes, warnings and "+1 hour"

PartHow it works
ActionsTurn on, Standby, Turn off, or apply a scene.
TargetThe room, one group, or one EPS unit (whole-unit power, still with every safety rule from section 6). Standby isn't possible for a single EPS unit, so such an entry is skipped.
DaysPick the weekdays. With none picked, the entry runs every day.
WarningBefore a Turn off or Standby entry, a full-screen warning appears in the last 15 minutes. It names what will switch off and can be dismissed.
Extend by 1 hourAvailable in the warning and in the power bar, up to 12 hours in total. It applies to that one entry only. Other entries still run on time, and when the extension ends only that entry's own target is switched.
PrecisionThe schedule is checked every 20 s, so an entry runs within the first 20 s of its minute. It follows the PC's clock and time zone.
Run one eXcontrol per installation. Two copies pointed at the same hardware each carry out their own schedule, so the room gets switched by both. If you set up a test copy, point it at test hardware or disable its schedule.

9 · What you see

One vocabulary everywhere

Every card, row and bar uses the same words and colours. Red means someone needs to look. Nothing else is red.

Why a device is in its state

Each card says which group decided, e.g. On · via Screens. When an Off device is kept powered for another device, its card says so, e.g. power stays on, output also feeds H9.

Pop-ups

If something comes back on after it was set to Off or Standby (a remote, a wall switch, another controller), a pop-up says what and when, e.g. "eXview turned On after it was set to Standby (Schedule: Power off, 17:00)." Dismiss it, or leave it for the next person.

10 · Other controllers

Companion, Crestron, Q-SYS: go through eXcontrol

Other control systems should send requests to eXcontrol instead of to the EPS directly. That way the same order of work and the same safety rules apply to their commands too. Group actions aren't in the Companion module yet, but its Generic HTTP module can call these directly.

If an access password is set (Setup › Access), it protects everything, including these requests. A controller logs in once and sends the bearer token it gets with every request. The token is valid for 30 days or until eXcontrol restarts. See Security.

11 · Not yet

Known limits of this version

Groups

No nested groups. Group targets aren't kept across a restart.

Supply

All EPS units are started one after another. There's no per-circuit "feeds" setting yet to run separate supplies in parallel.

Schedule

No exception dates (holidays). An entry missed while eXcontrol was down isn't caught up afterwards.

Companion

No group or eXview actions in the Companion module yet (use Generic HTTP).

Surfaces

Every browser sees the whole room. There's no per-tablet scoping to one group yet.

EPS firmware wishes (v2.3)

POWER_ON from partly-on that only adds missing outputs, a "busy" reply instead of dropping, a start offset per unit, and the firmware version in POWER_STATUS.
